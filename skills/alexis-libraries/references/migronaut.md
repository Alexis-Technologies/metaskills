# @alexify/migronaut

MongoDB migrations with single-file runs, real rollbacks, dry runs, an atomic lock, checksums and
declared collections. Version 2.5.0, tag `v2.5.0`, **Node.js 22.18+**, no runtime dependencies.
Peers: `mongodb` >= 5, and `mongoose` >= 7 as an optional one.

| Entry | Holds |
| --- | --- |
| `@alexify/migronaut` | `MigratorKit`, `createLogger`, `EXIT_CODES`, typed errors |
| `/bullmq` | each migration as a BullMQ job |
| `/versioning` | shape version and revision helpers: `updateWithRevision`, `bumpRevision`, `defineShapes` |
| `migronaut` (bin) | `up`, `down`, `redo`, `status`, `dry-run`, `create`, `import`, `baseline`, `converge`, `audit`, `lock`, `unlock`, `background` |

## When to choose it

| Change | Tool |
| --- | --- |
| Backfill, rename, data fix that must run once and in order | a migration |
| The current indexes, search indexes and validator of a collection | a declared collection and `converge` |
| Documents rewritten to a new shape `v` beside the application | a background migration, or the app's BullMQ job (auth8, ADR-017) |
| Existing database with a `migrate-mongo` changelog | `migronaut import` |
| Existing database with no migration tool | `migronaut baseline` |

Not for other databases, and not for changes to application data in a request path.

## Writing a migration

```js
module.exports = {
  description: 'Add unique index on users.email',
  async up({ db }) {
    await db.collection('users').createIndex({ email: 1 }, { unique: true });
  },
  async down({ db }) {
    await db.collection('users').dropIndex('email_1');
  },
};
```

TypeScript, ESM and CommonJS all load. The context holds `db`, `client`, `session` (in a
transaction), `signal`, `logger`, `run`.

`up` and `down` are both required: a file without one throws `MigrationInvalidExportError`.

```js
const up = async ({ db, session }) => {
  await db.collection('accounts').updateMany({}, { $set: { plan: 'free' } }, { session });
};

const down = async ({ db, session }) => {
  await db.collection('accounts').updateMany({}, { $unset: { plan: '' } }, { session });
};

module.exports = { useTransaction: true, up, down };
```

## Programmatic API

```js
const { MigratorKit } = require('@alexify/migronaut');

const migrator = new MigratorKit({ uri, dbName, migrationsDir: './migrations' });
await migrator.connect();
try {
  await migrator.up();
} finally {
  await migrator.disconnect();
}
```

| Method | Purpose |
| --- | --- |
| `up(file?, options?)`, `down(file?, options?)`, `redo` | run or revert |
| `dryRun('up' or 'down', file?)` | the plan, with no writes |
| `status()`, `list(filter)`, `audit()` | read-only state |
| `converge()`, `convergeHistory()` | bring declared collections to their state |
| `lockInfo()`, `forceUnlock()` | the deploy lock |
| `stop(reason?)` | stop after the current migration |

Configuration precedence: CLI flags, environment, config file, defaults.

## Validators from the model

The validator of a declared collection comes from metaschema, never by hand:

```js
// migronaut.config.js
import { toJSONSchema } from '@alexify/metaschema/generators';
import bson from '@alexify/metaschema/mongodb';

import { model } from './src/model.js';

const validators = toJSONSchema(model, { target: 'mongodb', ids: 'objectId' });
const indexes = bson.indexesOf(model);

const collections = [];
for (const name of Object.keys(validators)) {
  const definition = { name, validator: { $jsonSchema: validators[name] } };
  if (indexes[name]?.length > 0) definition.indexes = indexes[name];
  collections.push(definition);
}

export default { uri: process.env.MIGRONAUT_URI, dbName: 'app', collections };
```

The generated validator has `additionalProperties: false`. Declare every field the DAL writes
(`createdAt`, `updatedAt`, `createdBy`, `updatedBy`) in the model, or the database refuses the
documents.

## System fields: set the names

The `versioning` block and `@alexify/migronaut/versioning` default to double-underscore field names.
Alexis uses `v` and `rev`, so name them in every definition and helper call:

```js
const versioning = { current: 2, min: 1, field: 'v', revisionField: 'rev' };
const orders = { name: 'Orders', versioning };
```

Converge then adds the validator rules and the `{ v: 1, _id: 1 }` index. It refuses a validator that
already constrains the fields it manages, so remove `v` and `rev` from a schema generated by
metaschema before passing it (`withoutManaged` in `node-data-access`,
`references/schema-migrations.md`). A helper called without these options writes the default names,
so wrap the helpers once in the DAL. The block is experimental, like declared collections.

## Gotchas

- **Transactions need a replica set** and every driver call must pass `{ session }`. A call without
  it runs outside the transaction and is not rolled back.
- **Declared collections are experimental.** The shape may change in a minor release.
- Leaving out `indexes`, `searchIndexes` or `validator` leaves that part alone. `validator: null`
  means there must be none.
- An edited applied migration fails on its SHA-256 checksum. Write a new migration.
- A baselined migration is forward-only: `down` and `redo` refuse it.
- Out-of-order files only warn by default. Set `onOutOfOrder: 'error'` in CI.
- Several kits in one process: give each `envFile: false` and an explicit `uri` and `dbName`, or the
  first `.env` loaded leaks into the others through `process.env`.
- `converge` never drops an undeclared index unless `prune` is on. With `prune`, the declaration is
  the whole truth, and `recreate` and `drop` are destructive. Read `dry-run` output first.

Nothing here was run against a live MongoDB. The API and these rules are read from `index.d.ts`,
`docs/guide` and `docs/commands`. The `v` and `rev` options were checked against
`resolveVersioning` and `bumpRevision`.
