# RFC 6455 in practice: handshake, framing, own server

Read this when implementing or reviewing a WebSocket library, debugging
frames on the wire, or explaining how `ws` and the wrpc engine work under the
hood. Application projects use wrpc instead (see SKILL.md).

## Handshake

1. The client sends `GET <path> HTTP/1.1` with `Host`, `Upgrade: websocket`,
   `Connection: Upgrade`, `Sec-WebSocket-Version: 13` and
   `Sec-WebSocket-Key` (16 random bytes, base64, 24 chars). Browsers also
   send `Origin` and cookies; `Sec-WebSocket-Protocol` lists subprotocols.
2. Node.js emits `server.on('upgrade', (req, socket, head) => {})` on the
   regular `http.Server`. `socket` is the raw `net.Socket`; `head` is the
   first chunk already read after the headers and must be parsed as frame
   data (it may be empty or contain a whole frame).
3. The server answers on the raw socket:
   `HTTP/1.1 101 Switching Protocols`, `Upgrade: websocket`,
   `Connection: Upgrade`,
   `Sec-WebSocket-Accept: <base64(sha1(key + GUID))>`, then an empty line.
   The GUID `258EAFA5-E914-47DA-95CA-C5AB0DC85B11` is a fixed constant from
   the RFC; it works like a salt. If a subprotocol was requested, echo
   exactly one in `Sec-WebSocket-Protocol`.
4. To refuse, write a normal HTTP status (`400`, `401`, `403`, `404`, `426`
   with `Sec-WebSocket-Version: 13`) and close the socket.

Validation done by the wrpc engine before accepting
(`src/websocket/server.js`): path match, optional `verifyClient`,
HTTP/1.1, `Host` present, method `GET`, `Upgrade` equals `websocket`,
`Connection` contains `upgrade`, version `13`, a valid key. Write the
response headers inside `socket.cork()`/`socket.uncork()` so they leave in
one TCP packet.

WebSocket is not "raw TCP": it starts as HTTP/1.1 and is upgraded. A
WebSocket-only server can still run on `net.createServer()` by parsing just
enough HTTP for the upgrade, but then it cannot serve normal HTTP on that
port.

## Frame layout

| Bits / bytes             | Meaning                                                   |
| ------------------------ | --------------------------------------------------------- |
| byte 0 bit 7 (`0x80`)    | FIN: last fragment of a message                           |
| byte 0 bits 4-6 (`0x70`) | RSV1-3: must be 0 without negotiated extensions           |
| byte 0 bits 0-3 (`0x0f`) | Opcode: 0 continuation, 1 text, 2 binary, 8 close, 9 ping, 10 pong |
| byte 1 bit 7 (`0x80`)    | MASK: 1 for every client-to-server frame, 0 from server   |
| byte 1 bits 0-6 (`0x7f`) | Length 0-125, or 126 (next 2 bytes), or 127 (next 8 bytes) |
| next 4 bytes if masked   | Masking key                                               |
| rest                     | Payload; when masked, `payload[i] ^= mask[i % 4]`         |

Rules that implementations get wrong:

- Client frames must be masked and server frames must not; a violation is a
  protocol error (close `1002`).
- Control frames (close, ping, pong) have `FIN = 1` and payload <= 125 bytes,
  and may arrive between fragments of a data message.
- Text messages must be valid UTF-8 after reassembly (`isUtf8(payload)`
  from `node:buffer`; there is no `Buffer#isUtf8` method), otherwise close
  `1007`.
- A close frame payload is a 2-byte big-endian code plus a UTF-8 reason.
  Answer a close with a close, then the server closes TCP first; use a
  timeout (the wrpc engine uses 1 s) and `destroy()` if the peer never answers.
- Lengths above `Number.MAX_SAFE_INTEGER` and messages above your limit
  must be rejected before buffering (close `1009`).
- TCP is a byte stream: one `data` event may hold half a frame or several
  frames. Accumulate bytes, compute the expected frame length from the
  header, and parse in a loop.

## Pitfalls of a naive prototype

A 100-line server written to show the protocol is a teaching step, not a
template. The usual faults:

- assumes one `data` event is exactly one frame (no buffering);
- handles only short text frames (`0x81`), no continuation, binary, close or
  pong;
- starts a `setInterval` ping per connection and never clears it (timer and
  socket leak after disconnect);
- no message size limit, no key/version validation.

A production engine, such as `src/websocket/connection.js` in wrpc, handles
all of these: chunk buffering, fragment assembly with a size cap, UTF-8 checks,
mask direction checks, a close handshake with a timer, one shared heartbeat, and
a `send()` that returns `false` above the high-water mark.

## Minimal correct server (verified on Node.js 24)

Text frames, ping/pong and close, with buffering across TCP chunks. It
passes messages of 5 B to 300 KB from the Node.js global `WebSocket` client.
Continuation frames and binary messages are left out for brevity.

```js
const http = require('node:http');
const crypto = require('node:crypto');

const MAGIC = '258EAFA5-E914-47DA-95CA-C5AB0DC85B11';
const OPCODE = { TEXT: 0x1, BINARY: 0x2, CLOSE: 0x8, PING: 0x9, PONG: 0xa };
const MAX_BUFFER_BYTES = 1024 * 1024;

const acceptKey = (key) =>
  crypto.createHash('sha1').update(key + MAGIC).digest('base64');

// Returns a frame or null while the frame is incomplete
const parseFrame = (buffer) => {
  if (buffer.length < 2) return null;
  const fin = (buffer[0] & 0x80) !== 0;
  const opcode = buffer[0] & 0x0f;
  const isMasked = (buffer[1] & 0x80) !== 0;
  let length = buffer[1] & 0x7f;
  let offset = 2;
  if (length === 126) {
    if (buffer.length < 4) return null;
    length = buffer.readUInt16BE(2);
    offset = 4;
  } else if (length === 127) {
    if (buffer.length < 10) return null;
    length = Number(buffer.readBigUInt64BE(2));
    offset = 10;
  }
  const maskBytes = isMasked ? 4 : 0;
  const bytes = offset + maskBytes + length;
  if (buffer.length < bytes) return null;
  const mask = buffer.subarray(offset, offset + maskBytes);
  const payload = Buffer.from(buffer.subarray(offset + maskBytes, bytes));
  if (isMasked) {
    for (let i = 0; i < payload.length; i++) payload[i] ^= mask[i & 3];
  }
  return { fin, opcode, isMasked, payload, bytes };
};

// Server frames are never masked
const createFrame = (opcode, payload) => {
  const length = payload.length;
  let header = null;
  if (length < 126) {
    header = Buffer.from([0x80 | opcode, length]);
  } else if (length < 65536) {
    header = Buffer.alloc(4);
    header[1] = 126;
    header.writeUInt16BE(length, 2);
  } else {
    header = Buffer.alloc(10);
    header[1] = 127;
    header.writeBigUInt64BE(BigInt(length), 2);
  }
  header[0] = 0x80 | opcode;
  return Buffer.concat([header, payload]);
};

const accept = (req, socket) => {
  const key = req.headers['sec-websocket-key'];
  const version = req.headers['sec-websocket-version'];
  if (!key || version !== '13') {
    socket.end('HTTP/1.1 400 Bad Request\r\n\r\n');
    return false;
  }
  socket.write([
    'HTTP/1.1 101 Switching Protocols',
    'Upgrade: websocket',
    'Connection: Upgrade',
    `Sec-WebSocket-Accept: ${acceptKey(key)}`,
    '',
    '',
  ].join('\r\n'));
  return true;
};

const serve = (socket, head, onText) => {
  let buffer = Buffer.alloc(0);
  const write = (opcode, payload) => socket.write(createFrame(opcode, payload));
  const send = (text) => write(OPCODE.TEXT, Buffer.from(text));
  const receive = (chunk) => {
    buffer = Buffer.concat([buffer, chunk]);
    if (buffer.length > MAX_BUFFER_BYTES) return void socket.destroy();
    let frame = parseFrame(buffer);
    while (frame) {
      buffer = buffer.subarray(frame.bytes);
      if (!frame.isMasked) return void socket.destroy();
      const { opcode, payload } = frame;
      if (opcode === OPCODE.TEXT) onText(payload.toString(), send);
      if (opcode === OPCODE.PING) write(OPCODE.PONG, payload);
      if (opcode === OPCODE.CLOSE) {
        return void socket.end(createFrame(OPCODE.CLOSE, payload));
      }
      frame = parseFrame(buffer);
    }
  };
  socket.on('data', receive);
  if (head.length > 0) receive(head);
};

const server = http.createServer((req, res) => res.end('Use WebSocket'));

server.on('upgrade', (req, socket, head) => {
  socket.on('error', () => socket.destroy());
  if (!accept(req, socket)) return;
  serve(socket, head, (text, send) => send(`echo: ${text}`));
});

server.listen(8000);
```

Check the accept computation against the RFC example:
`acceptKey('dGhlIHNhbXBsZSBub25jZQ==') === 's3pPLMBiTxaQ9kYGzzhZRbK+xOo='`.

Optimizations for a library (not for app code): unmask
in place instead of copying when the input buffer is not reused, avoid
`Buffer.concat` per chunk by tracking the needed byte count, and benchmark
CPU, memory and event loop utilization against `ws`.

## Node.js client side

- Node.js 22+ exposes the WHATWG `WebSocket` globally (undici; experimental
  behind a flag in 21). There is no built-in server.
- `binaryType` defaults to `'blob'`; set `'arraybuffer'` for binary.
- `close(code)` accepts only `1000` or `3000-4999`.
- There is no `drain` event and no `ping()` method; `bufferedAmount` is
  available.
- Non-standard second argument `{ headers, protocols }` sets upgrade headers
  (useful for service-to-service auth). Browsers read the second argument
  as subprotocols only and throw on such an object, so keep this in
  Node-only code.
- On Node.js 22 a refused handshake may emit `error` without `close`; do not
  call `close()` synchronously inside that handler.
